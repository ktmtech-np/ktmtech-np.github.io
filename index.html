Maps · GIS

Naksa नक्सा

A self-hosted map of Nepal: OpenStreetMap data in PostGIS, our own vector tiles, a MapLibre GL app, and OSRM routing for driving and walking. A map editor adds the local detail OSM lacks: houses, shops, galli alleys, entrances and road closures. It also ships a land-records demo, an "online Malpot".

  • Search tolerant of typos, in Devanagari or English, in about 0.1 s across Nepal
  • Routes go to a place's mapped entrance, using our own alleys and respecting closures
  • Upload GeoJSON, KML, GPX or Shapefiles, reprojected from UTM, MUTM or Everest
  • Parcel splits to exact areas in ropani-aana-paisa-daam, bigha or m²
  • Go
  • PostGIS
  • MapLibre GL
  • OSRM
  • Vector tiles

Messaging · Cryptography

Cipher

An end-to-end encrypted chat platform: text, files and images, 1:1 voice and video calls, and encrypted group calls and video conferences on LiveKit. The X3DH and Double Ratchet protocol lives in one Go crypto core, compiled to WebAssembly for the browser and gomobile for Android and iOS.

  • Private keys are non-extractable WebCrypto keys and never exist in JavaScript
  • A three-node Erlang realtime cluster loses no message and drops no call when a node is killed
  • Encrypted files up to 100 MB, with thumbnails and video processed before encryption
  • Prometheus, Loki and Grafana, a strict CSP, and 2,036 automated checks
  • Go
  • Erlang/OTP
  • WebAssembly
  • WebRTC
  • LiveKit
  • Kubernetes

Email · Systems

ktmail

A complete mail server in one Rust binary, built as a drop-in replacement for Postfix and Dovecot. It handles SMTP, submission, LMTP, IMAP4rev2, POP3, Sieve and ManageSieve, with SPF, DKIM, DMARC and ARC, and comes with a Gmail-style webmail.

  • Reads existing Dovecot Maildirs with the same UIDs, so clients don't download everything again
  • No unsafe code, a Landlock sandbox, and a fuzzed parser for every protocol
  • DANE, MTA-STS, SCRAM with channel binding, and OAuth logins
  • Full-text search, including the text inside Office attachments, plus 647 tests
  • Rust
  • SMTP
  • IMAP
  • Sieve
  • TLS 1.3

Approach

Plan, then build in phases

Every project starts with a written plan. Each phase has exit criteria and commands that verify it, and decisions are recorded when the build departs from the plan.

Own the stack

Self-hosted from the data to the protocol: our own tiles, our own crypto core, our own mail server, run with standard tools on hardware we control.

Prove it works

Thousands of automated checks, fuzzing, failure tests that kill nodes mid-call, and end-to-end browser tests with screenshots.
